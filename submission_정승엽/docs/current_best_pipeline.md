# 현재 최고 성능 파이프라인 총정리 (exp_030 기준)

이 문서는 2026-08-22 기준 **리더보드 최고 기록(1006.62, exp_030
`season_state_no_extrapolation`)**이 정확히 무엇으로 구성돼 있는지
정리한 것입니다. "피처가 왜 이렇게 결정됐는지", "모델이 뭔지", "보정이
어떻게 되는지", "그 뒤에 깔린 야구적 해석이 뭔지"를 한 자리에서
파악할 수 있게 하는 게 목적입니다.

원본 근거는 전부 `experiments/exp_*.md`와 `src/*.py`에 있고, 이 문서는
그걸 종합 정리한 것입니다 — 세부 숫자를 다시 확인하고 싶으면 괄호 안에
적어둔 원본 파일을 보세요.

## 2. 전체 파이프라인 흐름

```
공식 train.csv (2019-2024)
      │
      ▼
① 피처 엔지니어링 (row-local, 다른 행 정보 안 씀)
    - 공식 47개 원본 컬럼
    - EDA 파생 37개 (exp_001~004)
    - 투수 트랙맨 물리특성 5개 (exp_007)
    - 이번시즌 상태 16개 (exp_027) ← 가장 큰 개선
      = 총 105개 피처
      │
      ▼
② CatBoost 학습 (동일 피처/하이퍼파라미터, seed=42와 seed=1 각각)
      │
      ▼
③ 두 시드 예측 확률을 단순 평균 (exp_010)
      │
      ▼
④ Platt 보정 — "최신 시즌(2024)에 강하게 맞춘 버전" (exp_022)
      │
      ▼
⑤ 카운트(볼-스트라이크)별 잔차 추세 보정 (exp_029)
      │
      ▼
최종 확률 (0~1로 clip)
```

exp_023/026에서 시도했던 "2025로 전역 상수를 외삽해서 한 번 더
낮추는" 단계는 **exp_030에서 완전히 제거**됐습니다 — 실제 LB에서
역효과(-45.61)였기 때문입니다(6번 참고).

## 3. 피처: 어떻게 결정됐는가

### 3-1. 공식 baseline 47개

`test.csv`의 `row_id`를 뺀 모든 컬럼(범주형 3: `top_bottom`,
`game_type`, `base_state` / 수치형 44). 공식 baseline 노트북 그대로.
전부 유지 — exp_004에서 "중복돼 보이는 컬럼 8개를 빼보자"는 시도를
했지만 오히려 점수가 내려가서 기각(중복돼 보여도 CatBoost 트리
분할에는 각자 몫이 있었음, `experiments/exp_004_*.md`).

### 3-2. EDA 파생 피처 37개 (exp_001~004, `src/features.py`)

전부 "한 행 안에서만" 계산되는 값이라 다른 행을 절대 안 봅니다(대회
규정 6). 야구적 근거가 있는 것 위주로 뽑으면:

| 피처(그룹) | 야구적 해석 |
|---|---|
| `count_diff`, `count_total`, `two_strike`, `three_ball`, `full_count` | 볼카운트 자체가 투수의 선택압을 결정 — 2스트라이크면 유인구를 던질 여유, 3볼이면 스트라이크존에 넣어야 하는 압박 |
| `pitcher_success_under_pressure` = 성공률 × `li`(레버리지 인덱스) | "중요한 순간일수록 제구가 흔들리는/좋아지는 투수"를 구분 |
| `pitcher_success_x_risp` (득점권 주자) | 득점권 주자 유무로 투수의 심리적 압박이 달라짐 |
| `pitcher_form_trend_isolated` = 최근 1경기 성공률 − "4~5경기 전만의" 평균 | 최근 폼 vs 예전 폼을 대수적으로 분리(prev1/3/5가 중첩 누적평균이라 단순 뺄셈은 최근 경기가 섞여 추세가 흐려짐 — `(5·prev5 − 3·prev3)/2`로 순수하게 "그 이전 구간만의" 평균을 복원) |
| `pitcher_form_volatility` | 최근 폼의 변동폭 = 그 투수가 "기복이 심한 타입"인지 |
| `same_hand_matchup`, `same_hand_x_{fastball,breaking,offspeed}_rate` | 전형적인 platoon(좌우 유불리) 신호 — 같은 손 매치업일 때 구종 의존도가 달라짐 |
| `three_ball_x_risp` | 3볼+득점권 조합에서 아웃카운트별로 비단조적인 패턴 발견(EDA) |
| `shrunk_pitcher_x_batter_success` | 투수 품질 × 타자 품질의 약한 곱셈적 상호작용(거의 가법적이지만 살짝 남는 잔차) |

**콜드스타트 보정(경험적 베이즈 shrinkage)**: `asof_pitcher_success_rate`
같은 누적 rate 컬럼은 표본이 적은 선수(이제 막 데뷔)일수록 우연에 의해
극단값이 나옵니다. `shrunk = (n·rate + k·prior) / (n+k)` 공식으로
표본이 적으면 리그 평균(prior) 쪽으로 당기고, 표본이 많으면 원래 값을
거의 그대로 씁니다. `k`는 투수 50, 타자 150(타자 쪽이 콜드스타트
편향이 4배 더 크다는 게 EDA로 확인됨).

### 3-3. 투수 물리 특성 5개 (exp_007, `src/trackman_pitcher_features.py`)

`trackman_history.csv`(구속·회전수·무브먼트 등 실측 데이터)를 공식
데이터에 없는 `pitcher_trackman_id` 매핑(`reports/trackman_id_mapping/`,
98%+ 투수 매칭, 99.67% 검증 정밀도)으로 연결해서, **투수 개인 단위**
as-of 평균을 붙였습니다.

- `trackman_rel_speed_asof`(구속), `trackman_spin_rate_asof`(회전수),
  `trackman_induced_vert_break_asof`/`trackman_horz_break_asof`(무브먼트),
  `trackman_extension_asof`(익스텐션)
- **야구적 해석**: "구위(stuff)가 좋은 투수일수록 제구 성공률도 다를
  것" — 실제로 리그 전체 단위·구종 "비율"로 시도했던 이전 버전(exp_005)은
  실패했지만, **개별 투수 단위 + 구종 비율이 아닌 물리적 "강도"**로
  바꾸자 처음으로 유효했습니다(`experiments/exp_007_*.md`).
- shrink_k=50으로 콜드스타트 보정.

### 3-4. 이번 시즌 상태 피처 16개 — 가장 큰 개선 (exp_027, `src/season_state_features.py`)

**이 프로젝트 전체 역사상 단일 최대 개선(+77.93, 로컬 740.86→818.79)**이자
현재 챔피언의 핵심입니다.

- **문제의식**: 공식 `asof_pitcher_*`/`asof_batter_*` 컬럼은 전부
  **2019년 데뷔 이후 커리어 누적** 값입니다. 그런데 리그 전체
  `control_success` 성공률이 2019년 0.565 → 2024년 0.486으로 계속
  떨어지고 있습니다(6번 참고) — 즉 커리어 누적 평균은 "그 선수가
  지금 얼마나 잘하고 있는지"를 항상 살짝 낙관적으로(과거의 더 높았던
  시절 포함해서) 보여줍니다.
- **해법**: 시즌 경계마다 "그때까지의 커리어 누적 스냅샷"을 저장해두고,
  각 행의 누적값에서 "직전 시즌까지의 스냅샷"을 빼서 **"이번 시즌
  들어서만"의 표본수/성공률**을 복원합니다. 데뷔 시즌(빼줄 이전
  스냅샷이 없음)은 자동으로 커리어 전체 = 이번 시즌 전체가 되어
  정확합니다.
- 이 값도 경험적 베이즈로 다듬습니다(shrink_k=20, 이번 시즌 초반이라
  표본이 적을 때 리그 평균 쪽으로 당김).
- **야구적 해석**: "이 투수가 커리어 통틀어 어땠는가"가 아니라 **"이
  투수가 올해 어떤 폼인가"**를 모델에 직접 알려주는 것 — 부상 복귀,
  기량 하락/상승, 폼 조정 등이 전부 이 피처에 반영됩니다.
- 팀원(허찬, `github.com/seokjin-wq/Aimers-9th`)의 130개 실험 중
  단일 최대 개선이었던 기법을 그대로 이식해 재현했습니다.

### 3-5. 최종 피처 개수 검산

## 4. 모델

**CatBoost 분류기(Logloss)**, 2개 시드(42, 1) 평균 배깅.

| 하이퍼파라미터 | 값 |
|---|---|
| `iterations` | 최대 2000 (early stopping, 실제 best_iteration은 시드마다 550~700 근방) |
| `learning_rate` | 0.03 |
| `depth` | 6 |
| `l2_leaf_reg` | 3.0 |
| `loss_function` / `eval_metric` | Logloss |

**왜 CatBoost인가**: exp_006에서 RandomForest/LightGBM/XGBoost/
ExtraTrees/Logistic 등 6개 아키텍처를 비교해 CatBoost가 최선으로
확인됐고, 이후 여러 번(exp_013 등) 재확인했지만 뒤집힌 적 없음.

**왜 2-시드 평균인가(exp_010)**: 같은 최강 모델을 다른 랜덤시드로
여러 번 학습해 평균 내면, 모델의 편향(bias)은 그대로지만 분산만
줄어듭니다 — Brier Score 같은 proper scoring rule에서는 이런 평균화가
이론적으로 손해를 보지 않습니다. 시드 5개까지 늘려봤지만 2개(42+1)가
최선이었고 그 이상은 오히려 살짝 나빠졌습니다(과도한 평균화로 개별
모델의 유용한 신호가 희석).

## 5. 보정(Calibration) — 여기가 이 프로젝트의 2차 핵심 축

모델이 뱉은 raw 확률을 그대로 쓰지 않고, 두 단계 사후보정을 거칩니다.

### 5-1. Platt scaling — "최신 시즌에 맞춘 버전" (exp_018 → exp_022)

```
보정된 확률 = sigmoid(a × logit(raw확률) + b)
```

2개 파라미터(a, b)짜리 아주 작은 로지스틱 회귀를 모델 출력 위에
얹습니다. 현재 챔피언의 값: **a(coef) = 4.35357716, b(intercept) =
−2.2176208**.

- exp_018: 2019-2023 데이터로만 학습 → LB +19.54
- **exp_022(현재 사용 버전)**: 2024 데이터를 학습에 큰 가중치(weight=100)로
  포함 → LB +19.96~20점대 추가
- **왜 2024를 가중치 주니까 더 좋아졌는가**: 성공률이 해마다 떨어지는데
  2019-2023만으로 학습한 보정기는 그 최신 하락분을 못 따라갑니다.
  2024는 이미 라벨이 있는 train 데이터라 이걸 보정기 학습에 쓰는 건
  규정 위반이 아니고(대회 규칙은 미평가 2025 test 통계 사용만 금지),
  2024를 강하게 반영시키자 "최근엔 더 낮다"는 걸 보정기가 직접
  배웠습니다.

### 5-2. 카운트 상황별 잔차 추세 보정 (exp_029, 팀원 EXP_127 이식)

Platt 보정은 **전역(리그 전체)** 드리프트만 잡습니다. 그런데
볼-스트라이크 카운트 조합(12가지)마다 드리프트 속도가 다를 수
있습니다 — 이걸 잡는 게 이 단계입니다.

**계산 방법**:
1. 각 행의 실제 라벨에서 **그 시즌 전체 평균**을 뺍니다(centering) →
   "이 count-state가 그 해 리그 평균 대비 얼마나 유리/불리했는가"만
   남김. 전역 하락분은 이 빼기로 상쇄되어 사라짐.
2. (count-state, 시즌) 조합별로 이 편차의 평균을 구하고, 5개 시즌
   점에 대해 OLS 회귀선을 그어 **그룹별 기울기**(연간 변화량)를 구함.
3. 그 기울기를 다음 시즌으로 한 스텝 외삽해서 예측 확률에 더함
   (`strength=1.0`).

```
최종확률 = Platt보정확률 + 1.0 × count_state별_기울기 × (외삽 스텝)
```

**야구적 해석**: 예를 들어 "3볼-0스트라이크"(투수가 무조건 스트라이크를
넣어야 하는 카운트)는 다른 카운트들보다 상대적으로 매년 조금씩 더
유리해지는 추세가 있었고(로컬 재현에서 연간 +0.0241), 이건 전역
평균 하락과는 별개의 신호입니다. **로컬 검증에서 exp_022/023 전역
보정 위에 +7.23점 추가 확보**했고, exp_027(이번시즌 상태)과는 완전히
다른 축(개인별 recency vs 상황별 drift)이라 독립적으로 유효함을
확인했습니다.

**주의(시행착오)**: 1차 시도 때 "count-state의 라벨 자체 추세"를
그대로 썼다가 -26.38로 대참사가 났습니다 — 우리 모델이 이미
`balls_before`/`strikes_before`를 원본 피처로 직접 쓰고 있어서, 라벨
추세를 그대로 더하면 모델이 이미 배운 신호를 중복으로 얹는 꼴이
됐기 때문입니다. **"그 시즌 평균 대비 편차"로 중앙화**한 뒤 추세를
잡는 2차 설계로 바꾸고 나서야 성공했습니다.

## 6. 야구적 배경 — 왜 "시즌이 갈수록 성공률이 떨어지는가"

이 프로젝트 전체 보정 전략의 근본 전제는 다음 관찰입니다
(`experiments/exp_022_recency_calibration.md`):

| 시즌 | `control_success` 비율 |
|---|---|
| 2019 | 0.5647 |
| 2020 | 0.5327 |
| 2021 | 0.5328 |
| 2022 | 0.5289 |
| 2023 | 0.5000 |
| 2024 | 0.4861 |

선형추세로 -0.01414/시즌. **이 원인 자체는 데이터에서 확인되는
현상이지 공식적으로 설명된 적은 없습니다** — 스트라이크존 판정 기준
변화, 투수 훈련법의 발전으로 인한 구위 상향평준화, 심판 판정
엄격화 등 여러 가설이 있을 수 있지만 이건 확정된 사실이 아니라
"관찰된 패턴"입니다. 이 프로젝트는 원인을 규명하려 하지 않고 **이
추세를 모델/보정에 얼마나 정확히 반영하느냐**에 집중했습니다.

## 7. 실패한 접근과 교훈 — exp_023/026 (중요)

**"2019-2024 선형추세를 그대로 2025까지 한 걸음 더 외삽해서 전역
상수로 확률을 낮추자"**(exp_023)는 로컬/walk-forward 검증에서는
그럴듯해 보였지만, **실제 LB에서 -45.61이라는 이 프로젝트 최대급
역효과**를 냈습니다(942.10 → 896.49). exp_027/029의 큰 로컬
개선(+85)도 같은 방식의 shift를 재사용한 exp_029에서는 LB에 거의
반영되지 못했습니다(898.87, 942.10보다 오히려 낮음).

**exp_030은 이 전역 상수 외삽만 빼고**(이번시즌상태+count-trend는
그대로 유지) LB 1006.62로 실제로 이전 최고 기록을 넘었습니다 — 즉
"2025는 이런 방향일 것"이라고 **전역적으로 단정해서 미는 보정**은
위험하고, 5번의 count-state 보정처럼 **국소적/상대적** 보정(전체
평균은 안 건드리고 그룹 간 상대적 차이만 조정)이 훨씬 안전하다는 게
이 프로젝트의 핵심 교훈입니다.
