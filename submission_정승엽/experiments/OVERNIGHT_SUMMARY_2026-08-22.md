### 4. exp_029 — count-state(balls×strikes) 시즌추세 보정 (완료, 채택)

팀원 EXP_127/130 이식. **1차 시도(라벨 추세 그대로)는 대참사**
(strength=1.0에서 -26.38, 모델이 이미 count를 피처로 써서 이중보정)
— **2차 시도(모델+기존보정의 잔차를 중앙화 후 추세)로 재설계해
+7.23(strength=1.0, 채택) 확보**, exp_027의 season-state 피처와는
다른 축(개인별 recency vs 상황별 drift)이라 독립적으로 유효함을
확인. `submission/archive/exp029_count_trend/`에 exp_027 위에
얹어서 아카이브 + 격리 테스트 통과. 기본 submit.zip은 exp_023로
원상복구. 상세: `experiments/exp_029_count_trend.md`.

**현재 로컬 검증 최고 후보 순위**(신뢰도 높은 순, 전부 LB 미검증):
1. exp_029 (exp_027 + count-trend) — 개념상 820.78+7.23≈828 대(직접
   합쳐서 재검증은 안 함, 각각 따로 검증됨)
2. exp_027 (season-state, 보정 포함) — 818.30(2시드), 보정 후 로컬
   held-out 근사 820.78
3. exp_023(현재 기본 submit.zip, LB 942.10 기준점) — 이미 LB 검증됨,
   가장 안전한 폴백

### 5. "역방향" 실험 — 완료 (성공적으로 예측 확보 + 검증)

1차 시도(`--only ols_slope`)는 study.toml 자체의 variant가 원본
GPU 설정이라 `CUDA error`로 실패. **CPU 전용 study.toml을 새로
만들어(`experiments/BASELINE_001_main55/study_cpuonly_repro.toml`)
재시도해 성공** — 팀원 파이프라인의 진짜 2024 holdout 예측을
`predictions_2024.csv.gz`(253,507행, row_id/target/probability)로
확보. 이 CPU 대체판 자체의 2024 holdout 점수: **940.30**(원본
945.44와 -5.14 차이 — GPU→CPU 대체로 인한 근사 오차로 추정).

**우리 보정(Platt/추세외삽) 얹어보기 결과 — 개선 없음, 이유가 명확함**:

| 지표 | 값 |
| --- | --- |
| 팀원 raw 예측 평균 | 0.4862 |
| 2024 실제 rate | 0.4861 |
| gap | **-0.0001**(사실상 0) |
| 순환(in-sample, 실제 held-out 아님) Platt 적용 시 | score +0.08만 개선, slope≈1.008, intercept≈0 |

**결론**: 팀원 파이프라인은 이미 count-state 잔차+추세 보정
(EXP_088/127/130)으로 시즌 드리프트를 사실상 완벽하게 흡수해서,
우리 exp_022/023식 보정을 얹을 여지가 **전혀 없음**(우리 보정이
푸는 문제를 팀원이 이미 다른 방식으로 풀어놨기 때문). **두 팀의
"시즌 드리프트 보정" 기법은 서로 대체재지 가산되는 관계가
아니다** — 반대로 우리 exp_027(원래 드리프트 보정이 약했던 베이스)
위에 팀원의 count-trend(exp_029)를 얹었을 땐 진짜로 +7.23이
났던 것과 대조적. 즉 "어느 쪽이든 자기 파이프라인에 상대방의
드리프트 보정 기법이 이미 있는지부터 확인해야 한다"는 일반적
교훈을 얻음.

### 오늘 제출 추천 (5회/일 제한 고려)

1. **exp_029 또는 exp_027을 최우선으로 1개 제출** — 로컬 개선폭이
   워낙 커서(+77~+87) 리더보드에서 확인하는 게 최우선. 이 프로젝트
   히스토리상 로컬 Brier 개선은 지금까지 항상 LB에서도 같은 방향으로,
   대개 더 크게 반영됐음(로컬-LB 델타가 118~158 사이, exp_022는
   델타가 오히려 더 커짐) — 그대로면 LB 1000 후반~1100대 이상도
   기대해볼 만하지만 **확인 전까지는 추정일 뿐**. 개인적으로는
   exp_029(exp_027+count보정 다 포함)를 먼저 추천 — 뭔가 잘못됐어도
   exp_027 자체는 이미 안전하게 검증된 별도 아카이브로 남아있음.
2. 결과가 좋으면(LB가 로컬 개선폭에 비례해서 오르면) 그날 남은
   슬롯으로 **exp_027 단독**도 하나 더 제출해 count-trend가 실제로
   추가 기여하는지 분리 확인 추천.
3. exp_023은 이미 검증된 안전판이니 굳이 오늘 다시 안 써도 됨(이미
   LB 942.10 계보 확인됨) — 급하면 그대로 둬도 손해 없음.
4. exp_026(증폭판), teammate_exp130_cpu_repro는 여유 슬롯이 남으면
   시도해볼 만한 참고용/대조군, 우선순위는 낮음.

### 확인 안 된 것 / 주의사항

- exp_027/029의 로컬 개선폭이 워낙 커서(+77, +87) 오히려 의심스러울
  수 있음 — 하지만 원인(팀원의 EXP_056/127을 코드 레벨까지 직접
  읽고 이식, 메커니즘도 이해하고 leak-safety도 확인함)이 명확하고,
  격리 테스트/실제 test.csv 값 확인까지 다 거쳤음. 그래도 **LB로
  실측하기 전까진 확정 아님**.
- "역방향"(팀원 예측 + 우리 보정) 실험은 완료함 — 팀원 파이프라인은
  이미 자체 count-trend 보정으로 시즌 드리프트를 거의 완벽히
  흡수해서(예측평균-실제rate gap이 -0.0001) 우리 보정을 얹어도
  개선 없음(섹션 5 참고). 두 팀의 드리프트-보정 기법은 가산되지
  않고 서로 대체재 관계 — 반대 방향(우리 베이스 + 팀원 기법)은
  실제로 +7.23이 났던 것과 대조적인, 나름 유용한 반례.
- 5-fold OOF의 원시 점수(~2100대)는 교차검증 낙관편향이라 절대
  신뢰하면 안 됨 — 위 표의 로컬 점수는 전부 진짜 held-out(2024)
  기준.
