# LG Aimers 9기 온라인 해커톤 대회 개요

## 한 줄 요약

투구 직전까지 확인 가능한 경기 상황과 과거 이력을 이용해 각 투구의
`control_success = 1`일 확률을 예측한다.

## 배경

스포츠 현장에서는 선수의 경기력 분석과 전략 수립에 데이터 기반 의사결정의
중요성이 커지고 있다. 야구의 투구 제구력은 다음 요소에 직접 영향을 준다.

- 실점 억제
- 볼카운트 운영
- 타자 대응 전략

평균자책점, 볼넷 수, 스트라이크 비율 같은 경기 후 집계 지표만으로는 개별
투구 직전의 복합적인 상황을 충분히 반영하기 어렵다. 실제 투구에는 볼카운트,
주자 상황, 투수·타자 특성, 과거 투구 이력 등이 함께 작용한다.

따라서 이 대회는 투구가 이뤄지기 전에 확인 가능한 정보만으로 해당 투구가
원하는 제구 범위에 성공할 가능성을 예측하는 문제를 다룬다.

## 주제

**투구 단위의 제구 성공 확률 예측 AI 모델 개발**

## 예측 대상

- 예측 단위: 개별 투구
- 타깃 컬럼: `control_success`
- 학습 데이터의 값:
  - `1`: 제구 성공
  - `0`: 제구 실패
- 제출값: 각 투구가 제구에 성공할 확률

확률 예측이므로 최종 출력은 `0` 이상 `1` 이하의 실수여야 한다.

## 제구 실패 정의

온라인 해커톤 Phase 2에서는 투구의 공 위치를 기준으로 제구 성공 여부를
정의한다. 다음 세 경우는 제구 실패이며, 그 외 유효한 투구는 제구 성공이다.

1. 스트라이크존 가운데 부근으로 들어간 공
2. 스트라이크존에서 크게 벗어난 공
3. 포수의 요구 방향과 반대로 들어간 공

## 모델이 활용할 수 있는 정보

문제 설명상 주요 입력 정보는 다음과 같다.

- 투구 직전의 볼카운트와 아웃카운트
- 주자 및 득점 상황
- 투수·타자 정보와 특성
- 투구 이전까지의 과거 이력
- 주최 측이 제공한 공식 학습 데이터
- 2019~2024년 과거 투구 특성을 담은 Trackman 보조 데이터

단, 평가 데이터에서는 각 행을 독립적으로 예측해야 한다. 다른 평가 행을
과거 이력처럼 사용해서는 안 된다. 구체적인 허용·금지 기준은
[`COMPETITION_RULES.md`](COMPETITION_RULES.md)를 따른다.

## 대회의 목적

Phase 2는 교육생의 문제 해결 능력을 검증해 약 100명의 Phase 3 진출자를
선발하는 온라인 해커톤이다.

Phase 3는 1박 2일 오프라인 해커톤이며, 세부 과제는 별도 안내된다. 온라인과
동일하게 야구 데이터를 기반으로 한 AI 문제로 진행될 예정이다.

## 코드 제출 방식

본 대회는 예측 CSV만 제출하는 방식이 아니라 `submit.zip`에 추론 코드와
모델을 담아 제출하는 코드 제출 대회다. 운영진이 제출 코드의 전체 추론
과정을 실행하고 검토할 수 있다.

| 항목 | 제한 |
|---|---:|
| 전체 추론 시간 | 10분 이하 |
| 평가 샘플 수 | 245,789개 |
| 패키지 설치 시간 | 10분 이하 |
| 제출 압축 파일 | 10GB 이하 |
| 압축 해제 후 크기 | 32GB 이하 |
| 인터넷 | 패키지 설치 외 오프라인 |
| CPU | 6 vCPU |
| RAM | 28GB |
| GPU | NVIDIA L4, 22.4GiB VRAM |

최종 제출 전 평가 탭과 코드 제출 가이드의 최신 내용을 다시 확인한다.

## 최종 제출 체크리스트

- [ ] 245,789개 행 추론이 10분 이내인가?
- [ ] 6 vCPU, RAM 28GB 제한 안에서 실행되는가?
- [ ] 필요한 라이브러리를 10분 안에 오프라인 실행 환경에 설치할 수 있는가?
- [ ] 인터넷 연결 없이 추론할 수 있는가?
- [ ] 제출 ZIP과 압축 해제 크기 제한을 만족하는가?
- [ ] 모든 확률이 `[0, 1]` 범위인가?
- [ ] sample submission의 `row_id`와 순서를 보존하는가?
- [ ] 평가 행 독립성 테스트를 모두 통과하는가?
